# Current release controls

**What runs, right now, in this repository.** One page, generated from the tree, so that
asking *"does a release produce an SBOM?"* has exactly one answer instead of four.

Four documents used to answer that question independently — `CONTRIBUTING.md`, `SECURITY.md`,
`RELEASE.md` and `docs/operations/licenses.md` — and after `FR-R3-099` retired every hosted
workflow on 2026-08-26, all four were wrong in different directions. One said the checked-in CI
workflows were configured for `develop`; one said the withdrawn scheduled audit was now run by
the gate, which does not run it; one said nothing generates an SBOM, which packaging does. The
repair is not four corrections. It is one derivation, and the four pages linking here.

## What this page is not

It is not a posture statement and it does not argue that the current set is the right one.
Whether a withdrawn control should come back is decided in
[withdrawn CI controls](withdrawn-ci-controls.md), which records what each one was and what it
cost to lose; what its runs actually produced is in
[the terminal record](actions-terminal-record.md). This page only says what is true today.

It is also not a list something must be added to. Every row is derived, so a control that
appears — a checksum producer in `scripts/`, a workflow that reappears, an `engine-strict` line — changes
its row on the next run, and a page that still describes the old state turns red. That is the
whole reason it is generated rather than written: the previous four pages were written, and
writing is what let them drift apart.

## Where the facts come from

| Fact | Read from |
|---|---|
| Hosted workflows | the count of `.yml`/`.yaml` files under `.github/workflows`, a directory deleted on 2026-08-26 |
| Audit in the gate | the transitive closure of `npm run gate` over `package.json` scripts, via `reachableScripts` in `scripts/check-gate-coverage-parity.mjs` — one authority on the closure, not two |
| SBOM on release | the same closure walk from `npm run release` |
| Checksums, provenance | a stated candidate set: the command bodies reachable from `npm run release`, plus every file under `scripts/`. An absence measured over an unstated set can never flip, which is the vacuity shape `tests/lint/gate-integrity/vacuity-detector.ts` exists to catch |
| Node floor | `engines.node` in `package.json`, and whether anything executed reads it |
