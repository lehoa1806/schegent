## 3. Schema Compatibility, Preserved Hard Rules & Security/Privacy Impact

- **Schema Compatibility**:
  - `STATE_SCHEMA_VERSION` (`src/state/workspace-state.ts`) and `SCHEMA_VERSION = 4` (`src/ui/sidebar/snapshot.ts`) are unchanged.
  - Durable control admission state is persisted under `KEYS.controlLedger` (`schegent.controlLedger`, `version: 1`) with a `ConnectedRunControlLink` (`version: 1`) on `ConnectedWorkflowRun.controlState`. Unknown top-level or per-root versions fail closed with `unsupported-control-ledger-version` and are never overwritten or deleted.
  - Regenerated contract schemas (`contracts/schemas/*.schema.json`) and webview type mirrors pass `npm run contracts:check` with zero diff.
- **Preserved Hard Rules (`docs/hard-rules.md`)**:
  - **Audit & Redaction**: Every recovery summary, slot error message, availability diagnostic string, and control-flow audit event passes through `SanitizedLogger` / `redactForAudit(...)` before persistence or IPC emission; metadata-only audit by default is preserved.
  - **Narrow File & Directory Modes**: All protected evidence files (`RecoveryEnvelope`, frozen `ForEach` collections, ordered `ForEach` result indexes) are written atomically via temp-and-rename with mode `0600` inside `0700` contained directories.
  - **Window Primacy & Workspace Trust**: `ControlCommandService` and the IPC router refuse mutating control actions (`check-now`, `try-now`, `select-candidate`, `set-policy`, `set-allowed-candidates`, `renew-monitoring`, `pause`, `resume`, `cancel`) when `isWorkspaceTrusted` or `isPrimaryWindow` is false.
  - **Headless Isolation & Non-Destructive Handover**: All availability checks use bounded read-only status probes (`<= 10,000 ms` timeout, max `3` concurrent checks) and never spawn prompt-charging CLI turns. Candidate handover preserves preexisting dirty and untracked files byte-for-byte and never executes destructive `git reset`, `git checkout`, or `git clean`.

## 4. Authoritative Measured Limits (`D1`–`D9`) & Accessibility Coverage

- **Measured Limits (`D1`–`D9`)**:
  - `CandidateBlock.candidates`: `1..8` unique candidates per block; `CandidateSpec.maxAttempts`: `1..20` (default `3`); `CandidateBlock.maxDispatches`: `1..40` (default `min(40, sum(candidate.maxAttempts))`).
  - Root Workflow Phase dispatches: `1..100` (default `100`, live tighten-only); dynamic control nesting depth: `<= 2`.
  - `RepeatControl.maxIterations`: `1..25` (default `3`), `carry`: `0..32` mappings.
  - `ForEachControl.maxItems`: `1..100` (default `50`), collection file `<= 262,144` bytes, item object `<= 8,192` bytes and `<= 32` primitive fields, ordered `resultIndex` `<= 262,144` bytes.
  - `structured-result` payload: `<= 262,144` bytes, `1..32` fields, strings `<= 1,024` UTF-8 bytes, selector depth `1..5` segments, max `32` array elements; `diagnostic-result` record `<= 65,536` bytes.
  - `RecoveryEnvelope`: `<= 16,384` UTF-8 bytes total, `<= 100` changed path entries (`truncated: true` and `coverage: 'partial'` on overflow).
  - `monitoringWindowMs`: `60,000..172,800,000` ms (`1m..48h`, default `86,400,000` ms / `24h`); readiness freshness `30,000` ms; minimum per-quota check interval `60,000` ms; deterministic jitter `0..5,000` ms; clock-drift invalidation `> 5,000` ms.
  - `ControlLedger`: max `20` live roots (evicting oldest terminal roots first), `1,024` frames/root, `2,097,152` bytes (2 MiB) per root with `16,384`-byte settlement reserve, `256` quota observations, `160` quota waiters, `3` active availability checks, `256` command receipts/root, `256` decision summaries/root, and `64` settled-check summaries/root.
