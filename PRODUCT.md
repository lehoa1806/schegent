# Product

## Register

product

## Users

Developers and technical leads operating automated software-delivery workflows from VS Code. They queue work, monitor long-running phases, inspect evidence, and intervene when a run pauses, retries, or fails.

## Product Purpose

Schegent turns spec-driven CLI workflows into an observable, controllable operator experience inside VS Code. Success means users can start work quickly, understand the current state at a glance, and act safely without leaving their development context.

## Brand Personality

Focused, technical, dependable. The product should feel native to a professional editor, calm during long-running work, and explicit when operator attention is required.

## Anti-references

Avoid glossy SaaS dashboards, decorative glass effects, neon gradients, marketing-style metric theater, novelty navigation, and visual treatments that compete with the user’s VS Code theme. Avoid hiding operational state behind ambiguous color or animation.

## Design Principles

1. Keep the workflow visible: current task, phase, evidence, and next action should stay easy to locate.
2. Earn attention with state: reserve accent color and motion for selection, progress, and operator feedback.
3. Make intervention safe: destructive and irreversible actions must remain clearly named, scoped, and confirmed.
4. Feel native to the editor: inherit VS Code theme and typography while giving Schegent a consistent surface hierarchy.
5. Prefer evidence over decoration: dense information is welcome when it helps users diagnose or decide.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Preserve complete keyboard operation, visible focus, screen-reader labels, reduced-motion behavior, theme contrast, and redundant state cues so color is never the only signal.
